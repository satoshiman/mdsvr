# Incremental OG Export

## Problem

OG generation is expensive (takes time and resources). Currently, every export re-generates OG for all files, even if content hasn't changed.

## Solution

Implement incremental OG export using hash-based change detection.

## Scope

- **Only applies to OG generation** (HTML export is fast enough to always re-export)
- Track file hashes across exports
- Only re-generate OG for files that have changed

## Hash Calculation

Hash should include:

1. **File content** - `sha256(fileContent)`
2. **Dependencies** - hash of all imported/required files (recursive)
3. **Global settings** - if settings affect OG rendering
4. **File path** - via key in state file (not in hash content itself)

**Note**: File path changes (move/rename) will trigger re-export because:

- OG images contain file URLs
- Path change → URL change → OG needs re-gen

## Implementation Plan

### 1. State File

- Create `.mdsvr-og-state.json` in `_html/public/og` directory (OG output directory)
- This ensures that when the OG folder is deleted, the state file is also deleted, triggering a fresh full export
- Format:
  ```json
  {
    "/path/to/file1.md": "sha256hash1",
    "/path/to/file2.md": "sha256hash2"
  }
  ```

### 2. Hash Calculation Function

```typescript
async function calculateFileHash(
  filePath: string,
  rootDir: string,
): Promise<string> {
  // 1. Read file content
  const content = await fs.readFile(filePath, "utf-8");

  // 2. Parse imports/dependencies
  const dependencies = extractDependencies(content);

  // 3. Calculate hash of dependencies (recursive)
  const depHashes = await Promise.all(
    dependencies.map((dep) => calculateFileHash(dep, rootDir)),
  );

  // 4. Include global settings if applicable
  const settingsHash = await calculateSettingsHash(rootDir);

  // 5. Combine all hashes
  const combined = [content, ...depHashes, settingsHash].join("|");

  return createHash("sha256").update(combined).digest("hex");
}
```

### 3. Export Flow

```typescript
async function exportOGIncremental(rootDir: string, outputDir: string) {
  const ogOutputDir = path.join(outputDir, "og");

  // 1. Load previous state
  const prevState = loadStateFile(ogOutputDir);

  // 2. Scan all markdown files
  const files = await scanMarkdownFiles(rootDir);

  // 3. Calculate current hash for each file
  const currentState: Record<string, string> = {};
  const changedFiles: string[] = [];

  for (const file of files) {
    const currentHash = await calculateFileHash(file, rootDir);
    currentState[file] = currentHash;

    // 4. Compare with previous state
    if (prevState[file] !== currentHash) {
      changedFiles.push(file);
    }
  }

  // 5. Only generate OG for changed files
  await generateOGForFiles(changedFiles, ogOutputDir);

  // 6. Clean up orphaned OG files
  const cleanedCount = await cleanupOrphanedOG(ogOutputDir, currentState);

  // 7. Save new state
  await saveStateFile(ogOutputDir, currentState);

  return {
    changedFiles: changedFiles.length,
    skippedFiles: files.length - changedFiles.length,
    cleanedFiles: cleanedCount,
  };
}
```

### 4. Dependency Extraction

- Parse markdown for imports: `import ... from '...'`
- Parse frontmatter for includes/references
- Handle relative paths

### 5. Settings Hash

- Calculate hash of `settings.json`
- Calculate hash of template files (if they affect OG)
- Include in all file hashes

### 6. OG Cleanup

After export, clean up orphaned OG files:

```typescript
async function cleanupOrphanedOG(
  ogOutputDir: string,
  currentState: Record<string, string>,
) {
  // 1. Get all existing OG files
  const existingOGFiles = await fs.readdir(ogOutputDir);

  // 2. Generate expected OG filenames from current state
  const expectedOGFiles = Object.keys(currentState).map((filePath) => {
    return generateOGFilename(filePath); // e.g., /docs/README.md -> docs-readme-og.png
  });

  // 3. Find orphaned files (exist but not expected)
  const orphanedFiles = existingOGFiles.filter((file) => {
    return !expectedOGFiles.includes(file) && file !== ".mdsvr-og-state.json";
  });

  // 4. Delete orphaned files
  for (const file of orphanedFiles) {
    await fs.unlink(path.join(ogOutputDir, file));
  }

  return orphanedFiles.length;
}
```

This handles:

- File renamed → old OG deleted
- File deleted → OG deleted
- File moved → old OG deleted

### 7. CLI Integration

- Add flag to force full re-export: `--force-og`
- Default: use incremental export
- Show stats: "X files changed, Y files skipped, Z OG files cleaned up"

## Edge Cases

### File Moved/Renamed

- Old key removed from state
- New key added with same content hash
- Result: re-export (correct, because OG URL changes)

### File Deleted

- Remove from state file
- No action needed for OG (output file cleanup optional)

### New File

- Not in previous state
- Always re-export

### Settings Changed

- All file hashes change (settings hash included)
- Full re-export (correct, because settings affect all OG)

## Performance Considerations

- Hash calculation is fast (sha256 is efficient)
- Dependency parsing adds overhead but worth it
- Can cache dependency parsing results
- Parallel hash calculation for multiple files
