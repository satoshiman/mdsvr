# Master Fix Plan: ADR-0006 → ADR-0009

> Kế hoạch tổng hợp triển khai các ADR đang ở trạng thái **Proposed** và **Accepted** gần đây: cô lập server instance state, hợp nhất page-rendering pipeline, chính thức hóa trusted-content policy, và source format tương thích GitHub.

---

## Các ADR liên quan

| ADR | Tiêu đề | Trạng thái | Vai trò trong plan |
| --- | --- | --- | --- |
| [ADR-0006](../../architech/02-adr/0006-isolate-server-instance-state) | Cô lập settings và cache theo server instance | Proposed | Phase 1 — Foundation |
| [ADR-0007](../../architech/02-adr/0007-unify-page-rendering-pipeline) | Hợp nhất page-rendering pipeline | Proposed | Phase 2 — Core refactor |
| [ADR-0009](../../architech/02-adr/0009-github-compatible-source-format) | Source content tương thích GitHub | Accepted | Phase 3 — Link transform & migration |

**Ràng buộc thứ tự**: ADR-0007 phải hoàn thành trước hoặc cùng ADR-0009, vì ADR-0009 dựa vào adapter boundary (`dynamic` vs `static`) được chuẩn hóa bởi ADR-0007.

## Phase 1: Cô lập server instance state (ADR-0006)

Mục tiêu: loại bỏ mutable state cấp module trong `server.ts`; mỗi `createServer` sở hữu context riêng.

### Tasks

1. **Introduce `ServerContext` type**
   - File tham khảo: `src/server.ts`
   - Định nghĩa:
     ```typescript
     type ServerContext = {
       settings: Settings;
       searchIndexCache: unknown; // thay unknown bằng kiểu cache thực tế
     };
     ```
2. **Di chuyển `currentSettings` và `searchIndexCache` vào closure**
   - Thay biến cấp module bằng object context được tạo trong `createServer`.
   - Truyền context xuống request handler thay vì import global.
3. **Cập nhật `reloadSettings` và watcher**
   - `reloadSettings` chỉ sửa context của instance gọi nó.
   - Watcher cleanup gắn với `close()` để tránh leak.
4. **Kiểm tra import nội bộ**
   - Tìm test/code đang import state toàn cục từ `server.ts`; refactor sang dependency injection hoặc public API.
5. **Thêm multi-instance integration test**
   - Tạo hai root khác nhau, start server trên hai port khác nhau.
   - Verify: reload settings của instance A không đổi title/search của instance B.

### Files dự kiến thay đổi

- `src/server.ts`
- `src/types.ts` (nếu cần export `ServerContext` nội bộ)
- `test/server.test.ts` hoặc `test/multi-instance.test.ts`

### Acceptance criteria

- Không còn biến mutable cấp module lưu `settings` hoặc `searchIndexCache`.
- Test chạy hai instance đồng thời pass.
- Watcher được đóng khi `server.close()`.

## Phase 2: Hợp nhất page-rendering pipeline (ADR-0007)

Mục tiêu: tách shared `page-rendering service` dùng chung cho router (HTTP adapter) và static exporter.

### Tasks

1. **Thiết kế contract `RenderPageInput`**
   ```typescript
   type RenderPageInput = {
     sourcePath: string;
     urlPath: string;
     rootDir: string;
     settings: Settings;
     mode: "dynamic" | "static";
   };
   ```
2. **Tạo application service `renderPageService`**
   - File mới: `src/render-page.ts` (hoặc `src/services/render-page.ts` nếu project đã có folder `services`).
   - Service chịu trách nhiệm:
     - Chọn Markdown/MDX renderer.
     - Đọc title, frontmatter, TOC.
     - Build sidebar.
     - Trả về rendered page model (HTML fragment + metadata + sidebar).
3. **Refactor router HTTP adapter**
   - `src/router.ts` gọi `renderPageService` và chỉ thêm HTTP concerns: status, headers, redirects.
4. **Refactor static exporter adapter**
   - `src/export.ts` gọi `renderPageService` rồi áp dụng link/asset transform, ghi file.
5. **Viết parity test**
   - Cùng source/settings, render qua dynamic mode và static mode, so sánh HTML body/sidebar/TOC.
   - Output chỉ được khác ở những phần đã tài liệu hóa (ví dụ: absolute asset path, trailing slash handling).
6. **Loại bỏ helper trùng lặp**
   - Xóa các hàm copy-paste giữa router và exporter sau khi test pass.

### Files dự kiến thay đổi

- Mới: `src/render-page.ts`
- Sửa: `src/router.ts`, `src/export.ts`
- Sửa: `src/renderers/*.ts` (nếu cần normalize interface)
- Mới/cập nhật: `test/render-parity.test.ts`

### Acceptance criteria

- Router và exporter đều gọi chung `renderPageService`.
- Parity test pass cho ít nhất 3 scenarios: plain Markdown, MDX, directory index.
- Public output không đổi ngoài khác biệt đã ghi chú.

## Phase 3: Source format tương thích GitHub (ADR-0009)

Mục tiêu: source viết link `.md`/`.mdx`; static export vẫn ra clean URL; dynamic serve có thể preview đúng export qua option `cleanUrls`.

### Tasks

1. **Thêm settings field `cleanUrls`**
   - File: `src/settings.ts` hoặc `src/schema.ts`.
   - Default: `false` để giữ backward compatibility, hoặc `true` nếu project muốn promote hành vi mới.
   - Cập nhật Zod schema, default generator, docs.
2. **Tái sử dụng hàm link transform**
   - Trích hàm `.md`/`.mdx` → clean URL từ exporter (sau Phase 2 nó nằm ở static adapter hoặc shared util).
   - Đặt vào `src/link-transform.ts` để cả HTTP adapter và static adapter dùng chung.
3. **HTTP adapter: rewrite link khi `cleanUrls` bật**
   - Trong HTML output của dynamic serve, rewrite internal link giống static export.
4. **HTTP adapter: redirect `308` canonical URL**
   - Khi `cleanUrls` bật, URL kết thúc `.md`/`.mdx` redirect 308 về clean URL.
5. **Giữ hành vi cũ khi `cleanUrls` tắt**
   - Router vẫn resolve `.md`/`.mdx` trực tiếp, không rewrite link.
6. **Viết parity test cho ADR-0009**
   - Cùng source viết link `.md`, so sánh HTML output giữa `cleanUrls: true` và static export.
7. **Migrate source content trong repo**
   - Chuyển các internal link trong `docs/`, `architech/`, `README.md` từ clean URL sang `.md`/`.mdx`.
   - Kiểm tra anchor và query string không bị mất.

### Files dự kiến thay đổi

- `src/schema.ts` / `src/settings.ts`
- Mới: `src/link-transform.ts`
- Sửa: `src/router.ts`, `src/export.ts`
- Mới/cập nhật: `test/github-source-format.test.ts`
- Sửa: `docs/**/*.md`, `architech/**/*.md`, `README.md`

### Acceptance criteria

- Link `.md` trong source hoạt động trên GitHub preview.
- Static export output clean URL không đổi.
- Serve với `cleanUrls: true` cho output giống export.
- Redirect 308 từ `.md` URL về clean URL khi `cleanUrls` bật.

## Phase 4: Chính thức hóa trusted-content policy (ADR-0008)

Mục tiêu: tài liệu hóa rõ mdsvr chỉ dành cho nội dung tin cậy; cập nhật docs, API docs, Docker example.

### Tasks

1. **Cập nhật `README.md` security section**
   - Thêm cảnh báo: Markdown HTML thô và MDX execution yêu cầu content tin cậy.
   - Phân biệt file-access protection (ADR-0004) với content sandboxing.
2. **Cập nhật programmatic API docs**
   - File: `docs/` hoặc `README.md`.
   - Ghi rõ MDX có thể thực thi code lúc render; chỉ dùng với docs root tin cậy.
3. **Thêm Docker read-only mount example**
   - Cập nhật `Dockerfile` / `docker-compose.yml` / docs nếu có.
   - Ví dụ: `docker run -v $(pwd)/docs:/docs:ro ...`.
4. **Rà soát security tests**
   - Đảm bảo test không tuyên bố bảo vệ vượt quá file-access guarantees.
   - Không gọi mdsvr là "sandbox".
5. **Cân nhắc CSP/security headers (optional defense-in-depth)**
   - Nếu triển khai, ghi vào docs là layer bổ sung, không thay thế trusted-content policy.

### Files dự kiến thay đổi

- `README.md`
- `docs/**/*.md`
- `Dockerfile` / `docker-compose.yml` (nếu tồn tại)
- `src/cli.ts` help text (nếu cần thêm cảnh báo)

### Acceptance criteria

- Policy xuất hiện nhất quán trong README, API docs, và security model doc.
- Release notes ghi rõ mdsvr yêu cầu trusted content.
- Không còn wording ngụ ý sandbox/sanitizer bảo vệ MDX execution.

## Test strategy

- Chạy `npm test` sau mỗi phase.
- Ưu tiên viết test mới trước khi sửa code (parity test cho Phase 2, multi-instance test cho Phase 1).
- Với Phase 3, thêm test render so sánh byte-for-byte HTML body giữa serve (`cleanUrls`) và export.
- Đối với migration source content, dùng `grep` hoặc validation script kiểm tra internal link không còn clean URL.

## Rủi ro và giảm thiểu

| Rủi ro | Ảnh hưởng | Giảm thiểu |
| --- | --- | --- |
| Refactor Phase 2 làm hỏng behavior cũ | Cao | Parity test trước khi xóa helper cũ; giữ một snapshot test về output HTML |
