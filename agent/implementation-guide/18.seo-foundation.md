# SEO-First Static Export — Implementation Plan

> Goal: upgrade mdsvr into an SEO-first static Markdown documentation generator.
> Strong per-page metadata, canonical URLs, sitemap.xml, robots.txt, JSON-LD,
> social metadata, `noindex` control — with zero-config defaults and full
> backward compatibility.
>
> Status: **Implemented**
> Created: 2026-10-04

---

## 1. Current State Audit

The project already has a partial SEO foundation. This plan extends it rather
than rebuilding it.

## 2. Design Decisions

### 2.1 Configuration (reuse existing conventions — no new top-level mechanism)

Keep the existing `_mdsvr/settings.json` schema and extend it minimally:

```jsonc
{
  "site": {
    "title": "Vuong's Docs", // = "site name"
    "description": "...",
    "baseUrl": "https://docs.example.com", // = "siteUrl" (keep name baseUrl)
    "language": "en",
    "author": {
      // NEW (optional)
      "name": "Vuong",
      "url": "https://example.com/about",
    },
  },
  "seo": {
    "titleTemplate": "%s | Vuong's Docs", // existing
    "twitterCard": "summary_large_image", // existing
    "twitterSite": "@handle", // existing
    "defaultImage": "/images/og.png", // existing
    "noIndex": false, // existing (site-wide)
    "generateSitemap": true, // existing
    "generateRobotsTxt": true, // existing
    "structuredData": true, // NEW: JSON-LD on/off, default true
  },
}
```

- **No `siteUrl` alias.** `site.baseUrl` already means the public origin; docs
  will describe it as the canonical site URL.
- `site.author` is optional; nothing author-related is emitted when absent.
- `seo.structuredData` (default `true`) gates all JSON-LD output.
- Zero-config keeps working: every new key is optional with a safe default.

### 2.2 Frontmatter schema (extend, don't fork)

```yaml
---
title: Terraform Remote State with GCS Backend
description: Learn how to configure Terraform remote state with GCS.
seoTitle: Terraform Remote State with GCS Backend | Terraform Guide # NEW
image: /images/terraform.png # existing
author: Vuong # existing (string; also allow {name,url})
date: 2026-10-01 # existing → treated as datePublished
datePublished: 2026-10-01 # NEW (explicit, wins over `date`)
dateModified: 2026-10-04 # NEW
noindex: true # NEW (lowercase; keep `noIndex` alias)
---
```

Field is always optional. `noindex` and `noIndex` both accepted (`noindex`
wins if both present); document `noindex` as canonical.

### 2.3 URL model — one canonical form

- Document routes are clean URLs with a **trailing slash**: `/terraform/remote-state/`.
- Homepage is `/`. `README.md`/`index` files map to the directory URL.
- Absolute page URL = `site.baseUrl` (trailing `/` stripped) + `generate.basePath` + normalized `urlPath` (trailing `/`), path segments `encodeURIComponent`-ed.
- When `site.baseUrl` is **not** configured:
  - omit `<link rel="canonical">` and `og:url` (never emit relative canonicals),
  - omit `og:image`/`twitter:image` relative-path upgrades are already handled — keep emitting the configured path as-is,
  - sitemap.xml: skip generation during **export** with a console warning (a sitemap requires absolute URLs); in **serve** mode use the actual request origin (`server.url`) instead of the hard-coded `localhost:1800` fallback,
  - robots.txt: omit the `Sitemap:` line entirely when no absolute URL exists.
- All of this behavior is documented in `docs/03-features/seo.md`.

### 2.4 Module layout (small focused modules)

```
src/
├── seo/
│   ├── index.ts          # re-exports
│   ├── url.ts            # normalizeUrlPath, buildPageUrl, escape helpers
│   ├── metadata.ts       # resolveSeoData(): frontmatter+content+settings → SeoData
│   ├── jsonld.ts         # buildJsonLd(): Article / WebSite / BreadcrumbList
│   └── extract.ts        # moved from renderer/markdown.ts: extractFirstHeading,
│                         # extractFirstParagraph (description, ~160 chars)
├── template/seo.ts       # buildSeoTags() — consumes resolved SeoData, emits <head> tags
└── generators/
    ├── sitemap.ts        # reworked: shared URL helpers, noindex filter, dedupe
    └── robots.ts         # moved out of static-export.ts
```

- `template/index.ts` calls `resolveSeoData()` then `buildSeoTags()` +
  `buildJsonLd()`; it no longer builds `SeoData` inline.
- `render-page.ts` passes the raw markdown `content` through so description
  extraction actually runs (fixes the current dead-code path).
- `static-export.ts` passes the collected `pageInfos` (urlPath + noindex flag +
  lastmod) to the sitemap generator for export, so page output and sitemap
  always agree. Serve mode keeps a scan-based path sharing the same helpers.

### 2.5 Title & description resolution

Title (displayed `<title>`):
`seoTitle` → `title` (frontmatter) → first H1 → humanized filename,
then formatted via `seo.titleTemplate`.

Default `titleTemplate`: to satisfy `<doc title> | <site name>` **without**
breaking existing sites, make `titleTemplate` optional in the schema. When
unset: `"%s | " + site.title` (or `"%s"` when `site.title` is empty). When set:
use it verbatim. Note: the built-in default today is `"%s"`; changing the
unset-behavior changes titles for sites that never configured the template —
accepted as the intended improvement (documented in changelog/docs).

Description:
`frontmatter.description` → auto-extracted first meaningful paragraph
→ `site.description`. Auto-extraction: strip frontmatter, code blocks,
headings, HTML tags/comments, nav-like lines; collapse whitespace; cut at
~160 chars on a word boundary (hard cap 200). Plain text only.

`og:type`: `website` for homepage and directory/auto-index pages; `article`
for document pages (no longer gated on `date`).

### 2.6 JSON-LD

One `<script type="application/ld+json">` per page containing a `@graph`:

- Document page → `Article`: `headline`, `description`, `url` (canonical,
  only when absolute), `image`, `author` (`Person`/`Organization` from
  site.author or frontmatter), `datePublished`, `dateModified` — only when the
  data exists. **No invented dates.**
- Homepage → `WebSite`: `name`, `url`, `description`.
- `BreadcrumbList` when `navigation.breadcrumbs` is on and the route has ≥1
  ancestor: built from `urlPath` segments + sidebar titles where resolvable.
- Serialization: `JSON.stringify` then replace `</` with `<\/` (prevents
  `</script>` injection). Emit nothing when `seo.structuredData: false`.

### 2.7 robots.txt

- Priority: custom `robots.txt` in docs root > generated.
- Generated: `User-agent: *` + `Allow: /` + `Sitemap: <absolute sitemap URL>`
  (only when an absolute URL is derivable). Optionally `seo.robots.rules`
  extra lines — defer unless requested; the custom-file mechanism already
  covers customization.

## 3. Implementation Phases

### Phase 1 — URL & extraction utilities

**Files:** new `src/seo/url.ts`, `src/seo/extract.ts`

- `normalizeUrlPath(urlPath)`: leading `/`, trailing `/` for doc routes,
  `index.html` collapsing, per-segment `encodeURIComponent`.
- `buildPageUrl(urlPath, settings, origin?)`: absolute URL or `null` when no
  base is available. Used by canonical, `og:url`, JSON-LD `url`, sitemap.
- Move `extractFirstHeading` / `extractFirstParagraph` here; tighten
  description cleanup (strip HTML, nav-ish lines, length ~160).

### Phase 2 — Metadata resolution

**Files:** new `src/seo/metadata.ts`, edit `src/render-page.ts`,
`src/template/index.ts`, `src/renderer/markdown.ts`

- `resolveSeoData({frontmatter, content, title, urlPath, kind, settings})`
  returns a normalized `SeoData` (title, description, image, absoluteUrl|null,
  type, dates, author, noIndex, breadcrumbs).
- `renderPageService` passes raw `content` into `renderPage`; directory pages
  get `kind: "directory"`.
- Remove the dead `rawContent` block in `template/index.ts`.

### Phase 3 — Head tags rework

**File:** `src/template/seo.ts`

- Emit: `<title>`, `meta description`, `meta robots` (`noindex, nofollow` when
  flagged), `meta author`, canonical (absolute only), full OG set incl.
  `og:site_name`, full Twitter set incl. `twitter:description`, article times,
  sitemap/RSS `<link>`s.
- Escape **all** attribute values including URLs.
- `og:type` = `article` for documents, `website` for homepage/directory.
- Resolve `frontmatter.image`/`seo.defaultImage` against `baseUrl` **and**
  `basePath` when absolute-form is possible.

### Phase 4 — JSON-LD

**Files:** new `src/seo/jsonld.ts`, edit `src/template/index.ts`,
`src/settings/schema.ts`

- `buildJsonLd(seoData, settings)` → JSON string for a single `<script>`.
- Inject after the SEO meta block in `<head>`.

### Phase 5 — Sitemap rework

**Files:** `src/generators/sitemap.ts`, `src/generators/static-export.ts`,
`src/router.ts`

- Export path: consume `pageInfos` (+ directory auto-index pages) — dedupe by
  normalized URL, skip `noindex` pages, `lastmod` from
  `dateModified`/`date`/mtime, encode URLs, XML-escape, sorted.
- No `baseUrl` → skip writing `sitemap.xml` in export + warn; serve mode uses
  request/server origin.
- Keep `changefreq: weekly` (harmless, documented).

### Phase 6 — robots.txt extraction & fix

**Files:** new `src/generators/robots.ts`, edit `static-export.ts`

- Move `generateRobotsTxt` out; only emit `Sitemap:` with an absolute URL.

### Phase 7 — Settings schema & validation

**Files:** `src/settings/schema.ts`, `src/settings/index.ts`

- Add `site.author`, `seo.structuredData`; make `seo.titleTemplate` optional.
- Update `generateDefaultSettings()` example and the JSON schema docs.

### Phase 8 — Tests

Extend `test/template.test.ts`, `test/static-export.test.ts`; new
`test/seo.test.ts`. Required coverage (verify **generated output**, not only
helpers):

1. title generation & `seoTitle` override
2. description generation & frontmatter override (~160 char rule)
3. canonical absolute URL; nested routes; homepage
4. `og:type` article vs website; `og:url` absolute; `og:image` resolution
5. Twitter incl. `twitter:description`
6. `Article`, `WebSite`, `BreadcrumbList` JSON-LD
7. sitemap contents, dedupe, noindex exclusion, URL encoding
8. robots.txt default, `Sitemap:` line only with absolute URL, custom override
9. `noindex` + `noIndex` frontmatter → `noindex, nofollow` meta
10. missing `baseUrl` behavior (no canonical/og:url/sitemap `Sitemap:` line)
11. HTML/XML/JSON-LD escaping (injection attempts in frontmatter)
12. backward compat: default config still builds; `noIndex` alias works

### Phase 9 — Documentation & verification

- Update `docs/03-features/seo.md`: full config reference, frontmatter fields,

## 4. Backward Compatibility

- No new required config; `npx mdsvr docs` unchanged.
- `noIndex` keeps working; `noindex` added as preferred alias.
- `robots.txt` custom-file override unchanged.
- Serve mode `/sitemap.xml`, `/feed.xml` endpoints unchanged (only URL origin
  handling improves).
- One intentional output change: default `<title>` gains `| <site title>`
  suffix; opt out with an explicit `seo.titleTemplate: "%s"`.
- One intentional tightening: sitemap skipped on export without `baseUrl`
  (previously emitted localhost URLs — invalid for real sites anyway; serve
  mode still works).

## 5. Edge Cases

- `/foo` vs `/foo/` vs `/foo/index.html` — one canonical trailing-slash form
  everywhere (HTML canonical, `og:url`, sitemap, breadcrumbs).
- Unicode / spaces in filenames — encode segments; sitemap locs XML-escaped.
- `README.md` + sibling `foo.md` collisions — dedupe normalized URLs.
- Frontmatter with `</script><script>` or quotes — never produce malformed
  HTML; JSON-LD uses `<\/` escaping.
- MDX frontmatter comes from `remark-mdx-frontmatter` — same resolution path.
- Directory auto-index pages — `website` type, included in sitemap, generic
  JSON-LD (no fake Article data).
